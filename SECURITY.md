# Security Policy

The Tynx engineering team takes product security and vulnerability reporting seriously.

---

## Reporting a Vulnerability

**DO NOT** file public GitHub issues for security vulnerabilities or sensitive findings.

If you believe you have found a security vulnerability in Tynx CLI, the Web Playground, or API infrastructure, please report it privately:

* **Email**: `security@tynx.dev`
* **Web Portal**: [https://tynx.dev/security](https://tynx.dev/security)

Please include:
1. A clear description of the vulnerability and its potential impact.
2. Step-by-step reproduction steps or proof-of-concept.
3. Affected versions of the CLI / website / compiler.
4. Any relevant system information (OS, architecture).

---

## Vulnerability Disclosure Timeline

* **Initial Response**: We aim to acknowledge receipt of security reports within 48 hours.
* **Assessment & Fix**: We will triage, develop, and test patches in private repositories before deploying updates.
* **Coordinated Disclosure**: Once a fix has been validated and released in a public version, we will coordinate public disclosure where appropriate.
